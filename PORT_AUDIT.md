### Save reset storage isolation

`resetEverything` directly deleted the browser localStorage key before updating the Zustand store, bypassing the configured storage adapter. This could delete an unrelated browser save during isolated tests and threw when browser storage access was denied despite a working configured backend. Reset now replaces the complete persisted payload through the store's own adapter, without a direct localStorage deletion.

The new isolated-process `savePersistence.test.ts` / `tests/save-round-trip.ts` regression failed at the direct deletion before the fix and now passes. It serializes real store actions, clears only live memory, and rehydrates through Zustand to check level continuation/unlocks, attempts, best score/time, diaries, scores, extras, statistics and settings. It also verifies progress-only reset preserves settings, full reset persists defaults, and neither touches a separate browser-storage sentinel. This is serialization/hydration verification, not an interactive browser reload or erase-dialog check. No actual user save was erased.

### Audio autoplay cannot block startup

The local browser reproduced a blank lab screen after level selection: it remained blank through several observations and reached the introduction only after a canvas click. `SoundSystem.initialize()` awaited `AudioContext.resume()`, whose autoplay request can remain pending until another gesture, while Game awaited initialization before loading the level and starting its loop.

Audio initialization now starts the resume request without waiting for permission. Pointer, keyboard and touch gestures retry a rejected/suspended request; listeners are removed after successful activation or destruction. Regression tests cover a never-resolving resume while initialization and sound decoding complete, rejected autoplay followed by input, and listener cleanup. After reloading the corrected app and selecting the lab, the introduction appeared without another canvas click. This does not bypass browser audio permission or assert that every browser's audio policy has been tested.

The same permission gap existed after pausing: `resumeAll()` discarded a rejected resume promise and never reinstalled gesture retries. A new regression failed with unhandled rejections and no retry on touch. Startup and gameplay resume now share the guarded gesture fallback. The test verifies rejected resumes, recovery on a later gesture, listener removal after success, and no gesture-driven unlocking while gameplay is deliberately paused. A reloaded browser build also passed ordinary pause/resume followed by movement, with no console errors/warnings; denied permission is covered by the regression test, not a browser permission-policy override.

Latest checks: **479 tests pass across 99 files**, typecheck and lint pass, production build passes with the existing large-bundle warning. These tests do not substitute for complete interactive campaign verification.
